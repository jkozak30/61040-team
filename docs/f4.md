The following table summarizes the design changes we have made from F3 to F4:

| Concept | Changes from F3 to F4 (concept and relevant reactions) |
| --- | --- |
| **Authenticating** | **Added from F3.** As planned, we adapted `Authenticating` from ConceptBox, and expanded the base concept's functionality to handle account creation (includes username/password verification upon registration and sign-in). |
| **Sessioning** | **Added from F3.** As planned, we adapted `Sessioning` from ConceptBox. We expanded its purpose to "identify subjects across requests", and added one `replace` action to allow for both guest and account-based identification. |
| **Presence** | **Added from F3.** We added this concept to track active browser connections through heartbeats + expiration. This replaces the participant `active` flag proposed in F3 to separate the ideas of storing room membership from tracking current attendance. Room presence still determines eligibility for ownership transfer, while live-watch presence determines whether anyone is still watching. |
| **RoomJoining** | **Retained** room creation + joining by code, display names, and ownership transfer functionality. <br>**Added** queries for reopening a room from history, and a new reaction for claiming a guest’s participation after signing in. <br>**Moved** attendance tracking out of RoomJoining’s `active` flag, and into Presence. Ownership transfer now uses the composition to check that the successor is a currently present account member. |
| **Watching** *(formerly Streaming)* | **Retained** the ordered video list, shared play/pause/seek controls, switching a selected video, and keeping videos available for local playback. <br> **Renamed** Streaming to Watching to better describe this scope for watching multiple videos. <br> **Added** (through reactions) automatic ending when the last live connection leaves or expires. <br> **Changed** reactions to allow any connected live viewer to switch videos or end the watch. Starting the watch and adding videos remain owner-only, and owner departure does not end the watch while others remain connected. |
| **Discussing** | **Retained** F3's timestamped threads on a video entry, nested replies, and discussion after the watch ends. <br>**Added** text checks, stable message ordering, and queries to resolve a thread or reply back to its video. The composition checks membership and video ownership on reads and posts, and live presence before labeling a post LIVE. This keeps a thread available for later review without letting its link bypass room access. |
| **Summarizing** | **Retained** on-request generation and saving an overview for each video’s discussion. <br>**Changed** summary input from plaintext to discussion threads with timestamps and messages; generated overviews include references back to the original thread. <br>**Added** Summary version validation, i.e. editing or deleting a comment invalidates the saved summary. |
